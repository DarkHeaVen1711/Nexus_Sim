====================================================================
1. WHAT IS NEXUSSIM?
====================================================================
NexusSim is a traffic simulation tool that recreates a real city's
road network on a computer and simulates thousands of vehicles
moving through it in real time. You can watch it live on a map in
your browser, just like watching live traffic.

The special thing about it: it uses Artificial Intelligence
(Reinforcement Learning) to control traffic signals, and it beats
the old-school fixed-timing method by about 35%.

It also measures FAIRNESS - not just "how fast are cars moving" but
"are people in ALL neighbourhoods waiting equally, or are some areas
always stuck at red lights?"

This is a 4-subject integrated college project:
  1. Reinforcement Learning  - teaches traffic signals to adapt
  2. Soft Computing          - optimizes simulation parameters
  3. Computer Vision         - sees and classifies congestion
  4. NLP                     - chat with the simulation in plain English

====================================================================
2. WHY DOES THIS PROJECT MATTER?
====================================================================
- In real cities, traffic signals run on fixed timings set years ago.
  Nobody updates them because it is expensive and risky to experiment
  on real roads with real commuters.

- NexusSim lets city planners test changes (like adding a bus lane or
  changing signal timings) on a computer FIRST, before spending money
  and disrupting real traffic.

- Unlike most tools that only care about "average speed," NexusSim
  also tracks whether the improvements are fair to all neighbourhoods,
  not just the rich ones.

====================================================================
3. HOW IS IT BUILT? (Simple architecture)
====================================================================

  [Data Pipeline - Python]
    Takes a city's map from OpenStreetMap, cleans it up, figures out
    how many lanes each road has, and creates a road network file.
    Adding a new city is just a config change - no code rewrite.

  [Simulation Engine - C++]
    The heart of the project. Loads the road network and simulates
    thousands of vehicles using physics-based car-following rules.
    Vehicles know how to follow the car ahead, stop at red lights,
    and find routes. Runs on all CPU cores for speed.
    Sends live data to the browser every frame via WebSocket.

  [Dashboard - React/TypeScript]
    A web page that shows a live map with moving vehicles. You can
    zoom in, switch cities, and see real-time statistics like average
    wait time and the fairness (Gini) score per neighbourhood.

  [ML Training - Python/PyTorch - runs offline]
    Trains an AI agent for each traffic intersection. The AI learns
    when to switch green/red by trial and error over thousands of
    simulated episodes. Trained policy gets exported to ONNX format
    so the C++ engine can use it directly (no Python needed at
    runtime).

5. WHAT HAS BEEN COMPLETED SO FAR
====================================================================

PHASE 0 - Project Setup ...................................... DONE
  Created the repository, build system, CI pipeline, and code
  formatting rules.

PHASE 1 - City Map Data Pipeline ............................. DONE
  Built Python scripts that download and process real city maps
  from OpenStreetMap. Chicago and Piedmont data are ready.

PHASE 2 - Vehicle Simulation + Route Finding .................. DONE
  5 types of vehicles (car, bus, auto-rickshaw, two-wheeler,
  pedestrian) that follow realistic driving rules and find their
  own routes using A* algorithm.

PHASE 3 - Performance Optimization ........................... DONE
  Added a quadtree spatial index so finding nearby vehicles is
  fast. Successfully tested with 20,000 vehicles - no crashes.

PHASE 4 - Live Map Dashboard .................................. DONE
  Built a React dashboard that shows vehicles moving on a real
  city map in real time. Only shows vehicles you can see on screen
  (viewport culling) to keep it fast.

PHASE 5 - Traffic Signals + Fairness Metrics .................. DONE
  Traffic lights work with fixed Webster's timing. Vehicles stop
  at red lights. Added fairness view showing per-neighbourhood
  wait times and Gini inequality coefficient.

PHASE 6 - Real Traffic Data + Validation ...................... DONE
  Loaded real Chicago rideshare trip data as vehicle demand.
  Validated that simulated travel times match real-world
  observations within about 20% error (MAPE).
  (Still working on getting more corridors within the target.)

PHASE 7 - AI Training Environment ............................ DONE
  Built a Gym-compatible environment to train AI traffic signal
  controllers. The trained RL policy beats the fixed Webster
  baseline by ~35% on a test grid (reward: -7,300 vs -11,270).
  48 ML tests passing.

PHASE 8 - AI Signal Control in Engine (Partial) ............... IN PROGRESS
  The C++ engine now has:
    - An ONNX inference engine that loads and runs the trained
      AI model directly (no Python needed at runtime).
    - A --policy flag to choose between Webster / AI control.
    - Batching of intersection observations for efficient
      GPU-free inference.
    - Graceful fallback to Webster timing if the AI model fails.
    - Benchmark and stress-test results committed.
  Remaining: full-city training (Phase 9) and dashboard policy
  toggle (Phase 10).

7. WHAT IS STILL PENDING (Honest Assessment)
====================================================================
1. Chicago validation: MAPE is ~21% but only ~64% of road
   corridors are within the 25% error target (need 75%).
   Root cause: river-bridge corridors create artificial bottlenecks.
   Fix planned: better lane capacity modelling + route diversity.

2. RL policy needs to be trained on the full Chicago graph,
   not just the toy test grid. (Phase 9)

3. Paris and Ahmedabad road networks are configured but not
   yet generated locally.

4. Dashboard has no real test suite yet (placeholder only).

5. Soft Computing, Computer Vision, and NLP modules are
   designed and documented but not yet implemented.
   (Planned for Phases 13-17)

9. HOW TO RUN THE PROJECT
====================================================================
Windows: Just run "run.bat"
  -> Builds everything, starts dashboard at localhost:5173,
     runs a 5-minute demo with 500 vehicles in Piedmont.

Chicago with real data:
  engine/build/engine --city chicago
    --od data/chicago/od_matrix.json
    --duration 60 --start-hour 8 --demand-scale 0.01 --fast

Train the RL model:
  cd ml && python -m train.train --city toy --episodes 500
